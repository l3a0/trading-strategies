# The shared estimators. ithildincore holds the OLS, ADF, half-life and
# Newey-West work this repo used to carry in common/timeseries.py and
# common/stats.py, and shares it with the sibling quantitative-trading
# repo, so one calculation has one implementation.
#
# Pinned to a commit, and pinned for a different reason than the linters
# below. A linter release breaks CI with no code change. A ithildincore release
# would change a number with no code change, and every pinned figure in this
# repo's significance blocks traces to that arithmetic.
#
# The commit rather than the tag `v0.1.0` it belongs to, because this repo
# installs with pip and keeps no lockfile, so a tag is the only thing between
# the pinned figures and a force-push. A tag can be moved on the remote. A
# commit cannot.
#
# Moving this pin is a re-pin, not a bump, and it carries two obligations the
# deleted common/stats.py docstring used to state at the point of edit:
#
#   1. Re-pin every figure that traces to the Newey-West block, which is both
#      daily judges, the factor IC, and the trade ledger.
#   2. Bump STRUCTURE_ENGINE_VERSION. `_data_lineage_hash` in
#      search/edge_search.py folds exactly the inputs that move the t-stat, and
#      this pin now moves it while sitting outside that hash. Without the bump
#      a re-scored campaign keeps its old lineage id, which is the stale
#      answer-key row the hash exists to prevent.

# The linters are PINNED while everything else floats, on purpose: a new
# ruff/pyright release adds rules that flag previously-clean code and breaks
# CI with no code change (ruff 0.16.0 did exactly this on 2026-07-23 —
# EXE001/RUF046 on files untouched for months). Bump these deliberately,
# clearing the new findings in the same commit, rather than have a linter
# release fail an unrelated PR. numpy/pandas/etc. don't have this failure
# mode, so they stay unpinned.
#
# ruff.toml now pins the rule SELECTION too, which is the durable half of this
# fix. Ruff 0.16.0 expanded its defaults from 59 rules to 413, so the 0.16.x
# bump raised 337 findings here with no code change. The repo's standard is
# written down now, so a ruff release can change its defaults without changing
# ours. Widening the rule set is a separate, deliberate change.
